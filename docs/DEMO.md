# ArtGate 8–10 分钟演示脚本

适用场合：腾讯 IEG 游戏管理平台产品实习面试。全程承认这是个人项目、公开资产、模拟项目组。

## 0:00–1:00  初衷（不要宏大）

「项目组其实不缺资产，缺的是把已有资产找回来，以及把明显不合规范的挡在入库前。文件夹和标签在外包一多就失效；面数、贴图尺寸这类问题本可以用工具秒查，却常常拖到 TA 人工验收才发现。CLIP 成熟之后，自然语言和概念图检索变成可做的事。但数面数这种事不该交给模型——所以第一层是规则引擎和官方校验器。」

## 1:00–2:30  平台化：同一套引擎，两套模板

打开「规范模板」页。对照：

- 风格化手游（M）：命名 `m_*`，面数约 2000，贴图上限 2048，不强制 PBR 通道。
- 写实（R）：命名 `r_*`，面数和贴图上限更高，贴图套装要求 albedo / normal / roughness，允许 ktx2（本评测集未覆盖真实样本）。

强调：换项目只换 YAML，不改代码。2 的幂次对 3D 贴图和 texture 类型强制，对 UI 精灵不强制——这是产品判断，可以用「同一张 1000×800，类型分别是 texture 和 ui」两条预检对比。

## 2:30–5:00  检索

项目选「风格化手游」。默认是 v2 混合检索。建议按这个顺序搜，讲「看坏例、做实验」：

- 「一把剑」「圆形盾牌」「长矛」、`a sword`：v1 语义 Recall@10 都是 0（常错成刀或锅盖），v2 能把 `weapon-sword.glb` / `shield-round.glb` 排到第一。讲机制：语义一路仍可能把刀排很前（「一把剑」语义约第 37），BM25 在扩展「剑→sword」之后命中文件名第 1，RRF 把它托上来。**模型本身没治好剑/刀**。
- 「长方形盾牌」：故意展示还没修好的。BM25 单独已经能召回 `shield-rectangle.glb`，混合后前 10 是带 rectangle 的 UI 按钮——两路都命中的干扰项挤掉了只在词法一路命中的正确答案。主动讲，不要等面试官发现。
- 「生日蛋糕」「金色冲锋枪」：看近重复和颜色扩展（金色→gold 也可能拉到 uziGold）。
- 再做一次以图搜图（用一把剑的预览）。切到写实项目搜「复古相机」，强调跨项目默认搜不到 Kenney 剑。

对照数字带 `eval/results_v2.md`，不要只报平均值。限制主动说：金标待审、词表作者见过 v1 坏例有泄漏风险、样本小、预览是自己渲的。

## 5:00–8:00  预检门禁 + 人工队列

提交几条队列里已准备的样本（或现场上传）：

1. `final_final2.glb`：命名 block，内容其实合法。
2. 1000×800 的 texture：POT block。对照 UI 同尺寸：不 block。
3. 超面数球体：面数来自 glTF-Transform，报告上有实测值 vs 阈值，没经过模型。
4. 文件名是盾、内容是剑：规则层通过；若开 mock，VLM 给 warn。强调默认不自动驳回。

然后 TA 改判：填原因，通过或退回。通过后才能被检索到。断开 VLM（backend=disabled）仍然只出规则报告。

## 8:00–10:00  边界、评测、你还没做的

- 何时不用 AI：能用工具算死的不用模型；模型只做写不死的视觉判断，并且默认不阻断生产。
- 打开 `eval/results_v2.md`：先讲 v1→v2 的 Recall 对比和那两条 BM25 能召回、混合后失败的例子。金标是自动起草的、你还没审；词表有泄漏风险。这些话主动说。
- 需求来源：还没访谈，【待实际访谈后填】。不是腾讯项目组经验。
